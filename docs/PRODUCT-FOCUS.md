# TAi Browser 当前产品方向

确认日期：2026-11-07。依据用户本次明确取舍，替代此前将剪藏资料库、共享阅读器和轻应用平台作为浏览器内置能力的规划。历史实现与检查记录保留，不能据此继续扩展已取消的产品范围。

## 内核与交付策略补充（2026-11-09）

用户确认保留现有 Chromium 内核，TAi 继续作为独立浏览器产品。当前不切换 Lightpanda、不增加第二套浏览器引擎，也不转为现有浏览器的伴随扩展。兼容标准 Chromium 扩展和日常浏览仍是约束。

资源效率先从 TAi 自身解决：退出取消的内置业务及其启动依赖，减少界面重建和无用轮询，随后测量实际页面/Space/Agent 并发开销再决定页面休眠、后台渲染和加载策略。不能把无头、关闭安全隔离或禁止网页正常工作当作轻量化结果；未测量前不承诺内存或速度提升比例。

## 原生账户入口暂时退出（2026-11-10）

用户要求暂时移除原生浏览器账户功能及右上角账户按钮，保留其他原生设置。当前按产品模式开关退出登录、同步、Profile 管理入口与命令；“常规”保留导入和浏览服务。已有 Profile 与站点数据继续保存，网站账号登录、密码/扩展及隐私能力不删除。恢复账号体验需另行产品决定，不因看到上游菜单代码而自动重新开放。About 与内部页身份采用 TAI 品牌，Chromium 版本/许可归属保留；原生设置页和顶栏统一实际文档底色。

## 产品范围

TAi 聚焦 Chromium 浏览器本身的配置、网页与标签组织、交互体验，以及外部独立 Agent 对浏览器的可靠控制。优先还原 Arc/Zen 等优秀产品中已经明确选定的交互，保留 Chromium 的扩展、下载、密码、权限和开发者工具能力。

| 方向 | 本次决定 |
| --- | --- |
| 浏览器配置与交互 | 核心开发主线：设置、Space/Profile、侧栏、标签、文件夹、快捷键、拖放、焦点和恢复 |
| 外部独立 Agent 控制浏览器 | 核心开发主线：成熟协议/客户端、明确授权与范围、稳定页面引用、并行控制与用户接管 |
| 剪藏、资料库、Markdown/JSON 阅读 | 退出内置产品范围，作为一个独立、可选的浏览器扩展方向；不继续内置资料库/阅读器接线和功能扩张 |
| 轻应用、Studio、番茄钟与自定义组件 SDK | 取消产品方向，停止预览/安装/版本平台、SDK 扩能、组件商店和相关通知/事件平台建设 |
| Chromium 扩展 | 沿用标准扩展机制和管理页；功能扩展不再要求使用 TAi 专用组件体系 |
| 内置聊天与快捷模型 | 不作为当前交付前置条件；先保证原 Agent 入口能控制浏览器，不新增 Agent runtime、规划器或调度器 |

剪藏扩展的独立边界已经确定，具体复用现成扩展还是从既有模块抽取，需要另做最小复用评估。当前不启动一轮替代插件开发挤占浏览器主线，也不宣称已经交付独立插件。

## 接下来按顺序推进

### 1. 收敛现有产品入口

- 从产品导航、设置和右栏中退出轻应用、番茄钟、Studio、内置资料库及独立阅读工具入口。
- 从面向外部 Agent 的默认工具和授权向导中退出轻应用候选提交与内置剪藏资料业务；保留网页读取、操作和浏览器组织能力。
- 保留现有用户资料文件、组件数据和历史版本记录。旧功能的用户数据不自动删除或迁移，不因重置浏览器设置清空。
- 先移除可见入口和继续执行旧功能的授权通路，再按依赖移除无调用的运行代码、打包资源和检查入口；不能顺手删除页面权限、隔离、IPC 或浏览器共用基础设施。
- 代码下线与原生构建需要单独实施和回归。本次方向记录本身不会改变已经安装的开发版，也不构成独立插件迁移完成。

### 2. 浏览器配置和交互

- 创建和编辑 Space 的名称、图标、颜色、Profile，明确设置生效范围，修复保存/取消/恢复与并发修改问题。
- 完成真实 Profile 与 Space 的关系，同窗口切换、跨窗口移动、账号隔离和重启恢复一致。
- 以实际操作打磨侧栏展开/完全隐藏/边缘浮出、Space 切换、标签关闭/恢复、多层文件夹和常用网站。
- 优先处理快捷键、地址栏输入、焦点、拖放命中与反馈、菜单、触控板、动画中断和减少动态效果，而非增加一组新工具页。
- 每轮选一个具体动作，与已有参考体验逐项比较，并在真实原生窗口验证；截图和静态布局不能替代交互验收。

### 3. 外部独立 Agent 的浏览器控制

- 保留原 Codex、Claude Code、Pi 等入口及各自模型、记忆、工具循环、批准和调度。TAi 提供浏览器接口和授权状态。
- 优先完善列页、打开/导航、读取、元素定位、点击/填写及标签/Space 组织；每次只补实际任务暴露的接口缺口，复用官方 MCP SDK 与 Chromium 现有能力。
- 请求固定绑定真实 Profile/Space，页面引用和修订可验证；多个 Agent 的目标明确，过期引用、并发写入、导航或移动后不能误操作其他页面。
- 验证 Agent 在一个目标 Space 工作时，用户在另一个 Space 的输入与焦点不被抢占；需要用户登录、原生弹窗或前台交互时提供明确接管。
- 连接配置、首次调用、错误提示、撤销和重连要能实际完成任务；不扫描个人认证，不暴露 Cookie、任意系统路径、通用脚本执行或无限制 CDP。
- 连接授权不冒充同会话聊天；右栏聊天、模型快捷功能和事件整理不作为浏览器控制链路的依赖。
- 页面修订、任务取消、授权撤销等浏览器控制状态仍按实际需要提供；退出的是轻应用与资料整理平台，不削弱控制链路所需的生命周期反馈。

## 验收与完成度

当前重点的验收是：无需组件体系即可日常浏览和配置；外部 Agent 在授权目标内完成真实网页任务；用户操作与 Agent 并行时归属、焦点和恢复正确；标准扩展与 Chromium 原能力不回归。

迁移仍按已有只读来源与原生事务边界推进，发行仍需独立构建、许可、签名/公证与干净机器验证。两者不因本次收敛而被宣称完成。

旧组件的历史测试通过只证明当时实现，不再增加当前产品完成度。退出产品后相应检查应随代码依赖明确归档；浏览器主干、数据保留、权限和 Agent 页面控制回归继续执行，不能通过关闭失败检查制造通过结果。

当前进度与未完成项以 [产品验收边界](PRODUCT-ACCEPTANCE.md) 为准；历史任务提示词只用于理解既有实现。
