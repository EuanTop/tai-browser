# TAi 设置与扩展边界

更新：2026-11-07。用户已明确收敛到浏览器配置、交互体验和外部独立 Agent 控制，见 [当前产品方向](PRODUCT-FOCUS.md)。剪藏/资料库/阅读转独立可选扩展，轻应用取消；本文件后半部的组件架构仅保留为历史记录。现有开发版的旧入口尚待下线，用户数据保留。

## Chromium 原有管理页

保留 Chromium 设置、历史、扩展管理、下载、密码/自动填充与网站权限等现有能力和数据归属，不重写管理页或做一份副本。工程上源码可以修改，但本项目把“不改写这些上游管理界面”作为维护约束。自有入口可跳转现有页面，不接管其生命周期。

本次核对锁定 Chromium 的 `chrome/common/webui_url_constants.h`：`chrome://settings/`、`chrome://history/`、`chrome://extensions/` 入口存在。导航必须落在用户选定的真实 Profile，不能在 Profile A 的 TAi 设置中无提示打开 Profile B 的扩展/密码环境。

TAi 可提供统一的设置入口和“浏览器设置/历史/扩展管理”链接；原 URL、原管理页、相关原生快捷键保持可用。不要把 WebUI 嵌入一个不兼容的 iframe，也不为了视觉统一复制维护历史/扩展列表和第二份浏览数据。

## TAi 独立设置

`chrome://tai/` 和侧栏齿轮已接入 Space 名称、颜色与 Profile 配色，沿用原生身份、版本校验和原子参数验证。实现与当前限制见 [原生设置](NATIVE-SETTINGS.md)。下表其余项目仍按模块逐步开发；没有展示 AI、资料目录等尚未生效的开关。

当前设置按以下范围收敛，按实际实现逐步开放，不展示无法生效的开关：

| 分类 | TAi 独有内容 | 范围 |
| --- | --- | --- |
| 外观与交互 | 侧栏宽度、完全隐藏/边缘浮出、Space 切换、减少动态、TAi 快捷键 | 明确应用级/窗口级；Space 颜色在对应 Space 操作 |
| Space 与 Profile | 创建/命名/绑定、现有 Profile 选择、身份提示、登录环境变化 | Space/Profile；浏览器原有扩展/密码等仍跳原管理页 |
| 外部 Agent | 渠道连接、目标窗口/Space、授权范围、调用状态、撤销与重连 | 固定真实 Profile/Space；不因设置页切换而改绑；内置聊天不作为前置条件 |
| 数据与迁移 | Chrome/Arc 可选导入、预览/批次、可移植导出、同步目录 | 明确来源/目标 Profile 与文件范围 |
| 关于与更新 | TAi Browser 品牌、产品与 Chromium 版本、许可、发行更新 | 应用级；开发状态不冒称已有更新服务 |

每一项显示影响范围和必要的重启/立即生效状态。TAi 设置重置只作用所选 TAi 配置，不隐式清除历史/Cookie/密码、剪藏原文或外部 Agent 任务。快捷键校验系统/浏览器/组件冲突，沿用系统“减少动态效果”。密钥保存在宿主安全存储，仅保存凭据引用，不同步到资料文件或给前端直接读取。

建议由 organizer 维护统一的设置注册/验证/持久化与渲染宿主：模块声明字段、默认值、范围、验证及组件内面板，不能直接任意写 PrefService/全局配置。简单设置用同一套控件；确有复杂流程再挂模块子面板。具体 schema 在 F0 冻结，文中不是已经存在的接口。

## 扩展与浏览器的当前分工

浏览器负责设置、网页/标签/Space/Profile、窗口与输入焦点、生命周期和外部 Agent 的受限控制接口。扩展沿用 Chromium 的安装、权限、存储、更新和启停体系；剪藏/资料库/阅读属于一个独立可选扩展的范围。TAi 不继续建立轻应用 SDK、商店或另一套扩展管理系统。

旧组件入口和 Agent 工具退出时不自动删除本地资料或历史数据；浏览器设置重置也不得借此清理旧数据。后续任何永久清理需另有明确用户授权。

## 历史插件与 TAi 原生组件设计（已退出当前路线）

“Agent 原生组件”在本工程指 TAi 自带的一等能力：有统一身份/数据模型/生命周期，普通用户可直接用，连接的 Agent 也能通过受限工具调用；它不是另一个 Agent runtime。“原生”描述产品整合，不要求全部用 C++，也不表示前端代码自动有系统权限。

| 层次 | 负责什么 | 管理方式 |
| --- | --- | --- |
| Chromium Extensions | 用户自行安装的通用扩展，如广告拦截、密码管理、网站增强；沿用标准扩展 API/权限 | 保留 Chromium 扩展管理，不为 TAi 另建副本 |
| TAi 内置组件 | Space/组件宿主整合、剪藏资料库、文档阅读等产品能力；共用产品身份、事件、工具与资料规则 | TAi 设置、产品维护版本、明确原生能力桥接 |
| 用户前端轻应用 | 番茄钟、侧栏小工具等，通过有限 SDK 使用授权能力，增量预览/应用/回滚 | TAi 组件面板和 manifest，不获得任意 Chrome 扩展/C++ 权限 |
| 外部 Agent | 用户选择的规划、工具循环、记忆、复杂改造与调度 | 原渠道配置与执行；TAi 仅连接和暴露获准能力 |

扩展同样可能操作浏览器或做剪藏，不能声称“扩展只能改网页”。TAi 组件的价值在于统一的原生入口、Profile/Space/任务规则、本地资料、生命周期与 Agent 工具：不要求用户为了基本剪藏先安装另一扩展，功能停用或 Agent 断开也不失去自己保存的文件。用户仍可自选第三方扩展，避免重复快捷键和后台重复剪藏，不能强制接管其数据。

## C/E/F 合并负责，内部保持分层

一个负责人维护三个协作模块，共用宿主 SDK：

- C 剪藏与资料库：提取/保存、内容规范/附件、索引/管理、Obsidian/Notion 目的地。剪藏与资料库为同一产品模块。
- F 阅读组件：Markdown/JSON 阅读、源码切换、净化/资源策略，被资料库和独立文件阅读复用。
- E 轻应用 SDK/示例：manifest、前端生命周期、预览版本和番茄钟，生成逻辑交已连接 Agent。

复用成熟开源剪藏提取器/内容脚本或库，但正式产品只保留一套 TAi 保存/设置/阅读/存储路径，不同时捆绑一整套带独立 UI/数据的剪藏扩展再叠一套原生实现。若某个能力确需内部扩展承载 DOM 提取，也只是受限可替换的实现细节，不出现两个用户入口或两份资料库。选型和许可先核验。

原生宿主、真实系统权限、目录/密钥/通知/页面访问、命令与事件的强制边界由 organizer 负责。合并负责人不需要等待大型“插件平台”建设：先冻结剪藏/阅读/轻应用所需的最小 SDK，不在一期重建通用第三方扩展商店或开放任意原生插件。
