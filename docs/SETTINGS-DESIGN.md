# Atrium 设置页：设计与验收

范围是 TAi 的 Space、外观、Agent 连接和浏览器管理四个设置分类，保留现有原生消息、实际 Profile 身份、revision 冲突校验及权限边界。此处不增加新 Agent 功能或恢复已取消组件。

## 观察与改变

1. **Space**：原界面重复标题、卡片右半空白、颜色井和输入框高度不统一，成功消息推动布局。改为图标/名称/颜色集中编辑、实时预览、固定反馈；图标弹出选择并支持窄屏、短窗口。保存和取消只在有草稿时可用，错误不会清空输入。
2. **外观**：文字下拉无法比较配色。改为使用已确认的标准与 Pride 建筑图的选项卡片，选中态、应用状态与未保存草稿分开。
3. **Agent**：统一渠道选择、权限展开、授权按钮和连接状态的尺寸与间距。配置、初始化和工具使用仍是不同状态，不用视觉“已连接”冒充实际通道。
4. **浏览器**：将散落链接改为一致的管理入口，继续打开实际 Chromium 设置、历史、扩展和下载页。

## 工程实现

`src/chromium/webui/tai.html/tai.css/tai.js` 保持原生 WebUI，不引入 React/Lit 或远程 UI 依赖；样式限于设置布局，首页继续由 home.css 控制。装饰图标复用 Chromium 的固定 SVG 几何，许可和修订见 REUSE-POLICY。`agent-setup.css` 为设置和右栏共用，不改变 Agent 授权协议。

`tools/preview_settings.mjs` 在自己创建的临时 Profile 中运行。默认模式通过 DevTools 注入本仓前端文件，使用现有原生消息接口，便于编译前反复检查视觉；`--built` 直接读取编译后的 WebUI，才是构建结果验证。两种模式的收据明确区分。它们均不附着用户窗口、读取个人 Agent 配置或修改用户 Profile。

## 检查边界

- 同一视口比较前后界面，检查四个分类、emoji 弹层、编辑预览、明暗模式及 760/480/360px 宽度；短窗口中弹层向上展开，不溢出视口。
- 功能检查覆盖草稿预览/取消、非法字段保留与定位、外观/Space 分别保存、多窗口冲突、原生写入及重启恢复。
- 原生构建与全部运行回归通过后再安装；本机交互额外检查实际窗口、鼠标、键盘与用户已保存的 Space 图标/颜色。
- 截图不代表完整读屏/键盘可访问性合规，合成 MCP 检查不代表个人 Codex App 模型对话验收。未进行全站或发行包兼容性承诺。


## 原生 About TAI 收尾（2026-11-10）

About 页使用单一卡片：64 DIP 高清产品图标、产品名及简短理念，随后以同一网格显示开发构建、实际 Chromium 内核版本和手动更新状态。移除产品页的无配置更新请求、错误图标/Google 更新帮助及 Chromium 产品帮助入口；版本详情和开源许可为明确的原生页面链接。原 Chromium 版权和开源归属完整保留在可展开的“开源致谢”，不改写成 TAi 的版权。受管理状态与系统过期提示保留。

颜色、文字、分隔线和卡片继续沿用原生设置变量；窄屏时信息由双列改为上下排列。图标从批准的透明原图缩放为 256px，再固定显示 64 DIP，不使用低清原图的自然尺寸撑大行高。中文和英文文案跟随原生应用语言。检查覆盖更新调用的产品/非产品差别、许可展开、版本与许可链接、1200/480/360px 视口和中文深色模式；实际构建及安装结果记录在 PRODUCT-ACCEPTANCE。

实际安装复核暴露了开发版 WebUI 辅助功能检查对信息列表 Term 命名的崩溃，已将该结构改为列表及静态文本，保持相同视觉顺序与布局。原生设置回归在进入 About 前启用 Accessibility 并获取真实 AX 树，核对更新状态可被读取；不关闭辅助功能检查或修改渲染器。

信息行使用原生设置常见的 Flex 行布局和统一标签宽度，回归比较三行数值的实际左边界；480/360px 时核对值位于标签下方。这样将列对齐本身纳入验收，而不只是检查页面没有横向滚动。
